# 清晰 PDF：小規模真實紙本掃描 OCR 驗證

日期：2026-10-12（台北）。基準 main：`4d697df9ac4e0288f0178ffd0b51630e7247e0de`。

## 結論與適用範圍

這輪驗證的是 **3 張真實紙本掃描頁、2 份文獻**，加上同一英文頁的正文裁切對照，
不是大型準確率評測。每個輸入以自動、單欄、雙欄各跑兩次；裁切不算新增實體頁。

- 英文正文雙欄可由自動模式維持先左後右；強制單欄會跨欄混讀。
- 全頁的跨欄頁首在中央分割模式被切成兩段，其中右半段移到左欄正文之後。
  這是現有雙欄模式已明示的使用邊界，不能把它描述為一般雙欄文件皆已支援。
- 繁中教材含手寫字形，主要問題是認成拉丁字母／數字或漏檢；改變欄序不能修復這些錯字。
  中英詞彙對照按列閱讀，與報章正文的欄序不同。
- 座標與文字匯出需和辨識品質分開判斷：保留 OCR 結果不等於那些結果正確。

本輪沒有修改正式 OCR 模組、預設模式、語言模型或 CER；不另造多欄辨識系統。
已知限制在 `dist/index.html` 的操作提示與既有 README 均有明確說明，因此不為
這些限制重做雙欄功能。是否另開修正 PR 依下方功能驗證和重現結果判斷。

## 方法與環境

- 準備階段用 PyMuPDF **1.26.6** 將來源頁轉為 PNG，300 DPI、最長邊 3500 px。
  再用專案內 pdf-lib 嵌入 image-only PDF，保留頁面尺寸並先證明 PDF.js 抽不到文字，
  避免來源舊 OCR 隱藏層誤走原生文字捷徑。無二值化、去噪、重畫或歪斜校正。
- 正式 UI 選擇 `chi_tra+eng`（教材）或 `eng`（百科），分別跑自動 PSM 3、單欄 PSM 4、
  既有中央分割 PSM 4。沒有 mock worker、注入答案或改寫 served OCR 程式。
- 沿用 `tests/support/scans.mjs` 的 `characterErrorRate`：NFKC、轉小寫、忽略空白／
  標點／符號；**不改算式、不截斷大於 1 的值、不把 CER 當 CI 門檻**。
- 本輪 Node **24.19.0**、Playwright **1.58.2**、Chromium **153.0.8010.0**。
  main 的 GitHub CI 使用 Node 22、Chromium 145.0.7632.6；本報告數字是本機 153 的結果，
  **不冒稱為 CI 145 的實測數據或跨版本一致性證明**。
- 每組兩次獨立 context／worker，無失敗重試。全文辨識後才進行校對測試。
- 量測保留 UI 全部文字與原稿框、TXT、原始／校對後 PDF、PDF.js 抽取項目、
  rendering mode、像素雜湊，以及來源、語言模型、引擎 loader、輸出檔的 SHA-256。

### 區分錯字、順序與漏檢

1. **標註區域 CER**：挑出與人工矩形相交的 OCR 行，保留原始輸出順序；一行只計一次。
2. **空間區域 CER**：依固定矩形分組後的補充觀察，可分離「區域之間」的排序影響，
   但仍含漏檢與區域內分行問題，不是純字形辨識率。缺失區域算刪除；跨多區域的行
   不任意拆字、不重複分配，個別 CER 記 N/A 並列出覆蓋字元數。
3. **閱讀順序**：另外記錄區域序列、逆序、跨區域合併及缺失；缺少左欄時，不因
   剩餘右欄由上到下就宣稱整頁順序正確。
4. **框位置**：除了頁內 bounds，也對照人工區域、記錄框面積落在區域中的比例。
   人工矩形是寬鬆區域標註，未提供逐字精準框，不能宣稱文字框定位全都準確。

區域匹配固定採 OCR 框垂直重疊 ≥50%、水平重疊 ≥較小寬度的 25%。
OCR 合併框可能帶入未標註的相鄰文字，或因框過大被排除，所以需一起檢視全文及框；
尤其密集百科的單欄數字，不可解讀為全文「超過 100% 字都辨識錯」，也不宜只比較小差值。

## 三種模式比較

**24/24 次功能案例通過**（完整頁 18 次＋配對裁切 6 次），無重試、無跳過。
12 個樣本／模式組合的兩次原始文字、文字框及重新計算的區域 CER／順序診斷完全一致。
辨識錯字與不適用版面的順序錯誤也同樣重現；功能通過不代表內容辨識正確。

以下是**標註區域 CER**，不是整頁或整份文件的準確率；越小越好。

| 輸入 | 自動 | 單欄 | 雙欄中央分割 |
|---|---:|---:|---:|
| 繁中例句（27 字） | 1.000000 | 1.111111 | 1.296296 |
| 中英詞彙配對（46 字） | 0.260870 | 0.239130 | 0.260870 |
| 英文完整雙欄頁（416 字） | 0.033654 | 1.074519 | 0.067308 |
| 同頁移除跨欄頁首（398 字） | 0.000000 | 1.115578 | 0.000000 |

### 純辨識、漏檢與欄序各自的證據

- **繁中例句**：自動／單欄把首句認成 `ro MPR HE RITA WP` 一類英數內容，
  在固定空間區域內計算的 CER 仍為 1.111111／1.148148，顯示主要不是欄序造成。
  自動模式缺少第 3 句的可匹配框。雙欄把三句都沿中央切成兩半，選定區域的輸出
  出現 `C1 → C2 → C3 → C1 → C2 → C3`，另有 3 個區域逆序關係。
- **詞彙配對**：自動／雙欄漏掉三個被標註的中文左側區域，只剩英譯；這是漏檢，
  不能解讀為「閱讀順序完全正確」。單欄有三個中英跨區域行，按同一列閱讀的語義
  合理，但仍有中文錯字；其空間區域 CER 記 N/A（0/46 字可無歧義拆成獨立區域），
  不為了數字好看強拆 OCR 文字。
- **英文完整頁**：自動模式沒有觀察到區域逆序，但有辨識／行框問題。
  雙欄將頁首拆成 `ENCKE—ENC` 與 `YYCLOPAEDIA 369`，右半段直到左欄正文後才出現；
  原稿框也顯示右半標題與頁碼被合併。標註區域 CER 0.067308，而固定空間區域 CER
  0.019231；加上明確的 5 個逆序關係，能看出排序與文字／框誤差同時存在。
  兩種 CER 的差**不是**可直接相減當成純排序錯誤率。
- **英文正文裁切**：自動與雙欄的 398 個標註字元皆無錯誤，區域順序皆為
  `L1 → L2 → R1 → R2`。單欄把左右同高內容合成一行，出現 2 個跨區域合併行及
  13 個逆序關係；這個樣本不適合單欄模式。

空間 CER 的覆蓋範圍與各區域實際字串完整記錄於
[原始量測 JSON](ocr-real-scans-20261012.json)。英文單欄的區域外內容會隨合併框進入
主指標，因此其 CER >1 包含多餘文字及排序因素，不能當作單純字形錯誤率。

### 文字框與 PDF 輸出

- 全部原稿框均為正面積且在頁內；這只證明數值有效。
- 完整英文頁左欄 `ENCLAVE` 摘錄，自動／雙欄的框面積約 **75.9%** 落在人工區域內；
  一個 OCR 框向上涵蓋前一段的小字，顯示框位置品質仍需檢視。
- 完整頁雙欄模式的頁首框只有約 **53.6%** 面積落在標註的標題區域，與右半標題
  合併頁碼的觀察一致。相對地，正文裁切的自動／雙欄四個標註區域約 **99.5–100%**。
  這些是框面積覆蓋比例，**不是**逐字定位準確率或通用 IoU benchmark。
- TXT 精確保留 UI 的原始文字與行序；PDF.js 重新抽取的文字與 UI 一致（只略空白），
  rendering mode 包含 3，頁面尺寸及可見 RGBA 像素雜湊均與輸入相同。
- 透過 UI 輸入獨立已知校對字串、儲存、重開、下載，再驗證 PDF baseline 與框轉換：
  `x = box.x`、`y = pageHeight - box.y - 0.85 × box.height`，寬度差小於 0.1 pt。
  完整首輪驗證每行，其餘 context 驗證首／中／末及每個已標註行；各次實際行索引在 JSON。

## 重現及交付範圍

完整指令見 [執行說明](../real-scans/README.md)。一般重現流程：

```sh
npm ci
npx playwright install --with-deps chromium
python -m pip install PyMuPDF==1.26.6
python tests/real-scans/prepare.py
node --test tests/real-scans/metrics.test.mjs
npm run test:ocr:real -- --repeat-each=2
node tests/real-scans/summarize.mjs
```

本次先跑 3 張完整頁的 18 次辨識，再在另一個輸出目錄跑配對裁切的 6 次；
彙總指令為 `node tests/real-scans/summarize.mjs real-scan-results real-scan-body-results`。
後者與前者部分並行，這不是效能／耗時 benchmark，不用本次執行時間推論速度。
日常 CI 不下載原始文件、不增加昂貴的歷史掃描測試。再次執行時瀏覽器版本可不同，
應以報告記錄的版本及雜湊核對，結果變化也應保留，而非調整標註以追求原數字。

## 尚未涵蓋

- **現代印刷繁體中文的真實雙欄頁**尚未加入；既有合成繁中 0 CER 不能替代這項證據。
- 這輪繁中只有手寫教材，只有 27 個純中文例句字元，不能估計一般繁中準確率。
- 不對稱雙欄、正式報表、跨欄正文／圖表、直排、照片透視與一般多欄均未系統驗證。
- 相同來源的配對裁切不是獨立樣本；相同頁重跑兩次也不增加樣本代表性。
- 全文尚無人工校對 ground truth，PDF 可見像素相同只證明匯出不改外觀。
