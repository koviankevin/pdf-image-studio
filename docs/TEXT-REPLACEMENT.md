# 掃描文件文字替換

使用者確認要將「框選舊字、以底色覆蓋、輸入新字」加進紙間。差異基準為 `b79eba2e572595a6917fcd20c8659ab2522c0839`，版本 0.10.0。

## 交付要求

1. 在現有文字／標記編輯器提供文字替換工具，能拖曳區域、輸入繁體中文、移動替換框，調整黑體／明體、字級、顏色、底色、範圍與文字留白。
2. 替換框與新字是一個可編輯項目，支援復原／重做及取消；文字依實際字寬換行，超出框時阻止儲存並提示調整，不默默縮小或截斷。
3. 共用正式 PDF drawing 路徑；PDF、PNG、框選輸出及 A4 排版沿用相同修改，區域外與未改頁面保留，PDF 保持原始圖片與向量，不為這項功能將整頁重繪成低解析圖片。
4. 自動草稿（含未失焦欄位）、關閉／重開與專案備份能保留修改；既有草稿及普通文字、螢光筆、箭頭、方框相容。
5. 新字型隨站提供，有來源 commit、SHA-256 及授權；首次使用才載入，失敗可重試，期間保留輸入且可取消編輯。
6. 介面清楚說明這是外觀覆蓋，原稿與既有 OCR 文字可能仍被擷取，非永久遮蔽或原稿段落重排，不承諾字型與掃描原字完全一致。
7. 完成受影響回歸、三種瀏覽器必要門檻及手機版面目視檢查，再依既有 main 流程發布與核對線上產物。真人／實機商品化驗收仍另行追蹤。

## WebKit 繪圖修正

Linux WebKit 對 PDF.js 暫存畫布採延後繪圖時，回收暫存畫布可能讓掃描頁消失。診斷 run `40502442721` 在解碼資料含 40,707 個非白色通道時，預設目的畫布畫出 0 個字跡像素；目的畫布使用 `willReadFrequently: true` 後畫出 2,641 個，與 Windows WebKit 的參考結果一致。停用 OffscreenCanvas 與原生解壓縮均無法修正。

正式 PDF 轉圖、縮圖、OCR 取圖、A4 預覽及輸出前預覽共用 `pdfCanvasContext`，只為 WebKit 選擇軟體目的畫布，保留 Chromium／Firefox 原路徑。測試維持嚴格像素比較，並新增縮圖必須含實際字跡的檢查；未更動第三方 PDF.js 或 PDF 內的原始影像。
